# Routing demo — proof of concept

Panel revision item 1: show what the query routing pipeline returns for a cited answer, an office referral, and an out-of-scope message, on a student-facing helpdesk site. **Answers are generated by gpt-4o-mini, a hosted stand-in** for the study's fine-tuned, 4-bit, offline Llama 3.2 3B. It's not fine-tuned, not quantized, and not the study's model, and the page says so. The plan is in `IMPLEMENTATION_PLAN.md`, and progress is in `SPRINTS.md`.

## Run it

1. **Once:** copy `.env.example` to `.env` and put your OpenAI key in it. `.env` is private: it's git-ignored, and it must never go on a shared USB stick.
2. **Start** (WSL, from `poc_thesis/`): `./run_server.sh`
3. **Open** `http://127.0.0.1:8000` in your browser. Flip **Developer view** in the header to see how each answer was made and the passages the model was given.

With no key, the site still runs: referrals and out-of-scope answers work, and cited answers explain that the generator isn't available.

## Where things are

| Folder | What |
|---|---|
| `shared/initial_check.py` | **Gate 0 · Initial check**, before any search: 0a English only (`language.py`), 0b one question (`questions.py`). Report: `docs/INITIAL_CHECK_REPORT.md`, re-run with `tools/test_initial_check.py` |
| `server/` | The live pipeline: `retrieve.py` (BM25 + meaning search + RRF), `route.py` (Gate 1, Gate 2, the three paths), `prompt.py` (the system prompt, the same one as in the training-sample design), `generator.py` (**the one swappable part**: today gpt-4o-mini, later the offline model), `citations.py`, `offices.py`, `api.py` |
| `web/` | The student-facing site: `index.html`, `styles.css`, `app.js` |
| `data/` | The knowledge base and lookup files (Sprint 1). See `data/README.md` |
| `shared/` | Code used by both tools and server: the BM25 tokenizer, the office keyword rule |
| `tools/` | Sprint 1 data builders and the data report |

**Python environment: for now, the old one.** During development the tools run with
`../ai_context/venv` (it already has everything installed). `.venv/` was created for a clean
environment but its install was stopped part-way; finish it with
`.venv/bin/pip install -r requirements.txt` before the demo has to run on another machine
(Sprint 3's USB-stick test at the latest). `requirements.txt` pins the exact versions the
report was measured with.

**Rebuild the data (Sprint 1)**, from `tools/`:

```
PY=../../ai_context/venv/bin/python             # later: PY=../.venv/bin/python
$PY build_demo_corpus.py        # inputs/corpus.json -> data/corpus_demo.jsonl + data/embeddings.npy
$PY build_office_exemplars.py   # handbook pp. 22-27 -> data/offices.json + data/office_exemplars.jsonl
$PY make_data_report.py         # -> docs/DATA_REPORT.md  (review this)
```

`pdftotext` (poppler-utils) must be installed for `build_office_exemplars.py`.

The first run downloads the embedding model (BAAI/bge-small-en-v1.5, about 130 MB) into the Hugging Face cache. After that, everything runs offline.

`shared/tokenizer.py` is the one BM25 tokenizer (regex + stopwords + Snowball stemming). There is no BM25 index file: the index is built in memory from `data/corpus_demo.jsonl`. `inputs/` holds copies of the old material, taken once. Nothing here reads from `ai_context/`.
